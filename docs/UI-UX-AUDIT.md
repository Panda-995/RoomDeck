# RoomDeck UI / UX 检查与改版记录

日期：2026-09-10。范围为实际 Vue 应用，包括登录、初始化共用表单、房间列表、加入房间、主持人控制台、参与者页面、分享、邀请、设置、内容操作、游戏与投屏。对照截图保存在 `screenshots/ui-before`，新版位于 `screenshots/ui-after`。

## 主要问题与处理

| 优先级 | 原问题 / 原因 | 本次处理 |
| --- | --- | --- |
| 高 | 手机断点样式先导入，随后被基础组件覆盖，造成尺寸和排列不稳定 | 重排样式加载顺序，重新组织响应式规则 |
| 高 | 投屏、游戏与内容类型同排，侧栏又重复一组入口 | 内容 / 投屏 / 游戏作为一级导航，类型筛选作为二级；手机参与者仅保留一套主导航 |
| 高 | 内容操作仅 29px 宽；下载链接未按按钮居中 | 图标操作统一 44×44px，下载图标使用相同布局；低频管理操作收进菜单弹窗 |
| 高 | 原生 dialog 在浏览器顶层，页面 toast 被遮在后面 | 维护弹窗栈，通知进入当前顶层弹窗；无弹窗时在页面顶部显示 |
| 高 | 上传重试未锁定 busy，允许中途切换类型或关闭 | 每项上传绑定类型，重试独立锁定，处理期间禁止误关；完成和失败状态可见 |
| 高 | 点击骰子或玩家立即提交，不容易撤回误触 | 先选择再确认，提交前明确提示本轮不能更改；选中状态可读 |
| 中 | 游戏轮询可能导致新选择被无关刷新清空 | 只在游戏身份、阶段、轮次或加赛状态变化时重置选择；新增轮询回归测试 |
| 中 | 弹窗滚动后标题和关闭按钮离开视口 | 固定弹窗头部；手机底部面板；关闭恢复焦点；Escape 与 busy 状态联动 |
| 中 | 上传原生 input 的 hidden 被 CSS display 覆盖 | 明确保障 hidden 语义，点选和拖放由统一上传区域承载 |
| 中 | 设置的开关、文字、下拉框尺寸不一致；英文语言选择被 72px 宽度截断 | 重做标签与开关行，选择框按内容自适应，表单统一尺寸 |
| 中 | 主持人的窄屏管理操作位于长内容流末尾 | 顶部提供现场控制、成员、设置快捷入口 |
| 中 | 参与者桌面仍固定显示手机导航；移动底栏与 toast 叠加 | 桌面隐藏底栏，手机增加底部安全留白，toast 移至顶部 |
| 中 | 英文 320px 一级导航过宽 | 手机导航采用等宽布局并允许长名称换行 |
| 中 | 开启大屏先等异步请求，再打开窗口，可能失去点击授权 | 点击时立即创建窗口，取得配对令牌后导航；被阻止时给出明确说明 |
| 中 | 卧底词在切换区域后可能保持展开 | 切换区域、窗口失焦或页面隐藏时收起；普通同步不强行打断查看 |
| 低 | 白底卡片再套白底面板，层级依靠过多边框 | 移除内容区外层边框，以留白分区；便签、链接使用克制的语义底色 |
| 低 | 同一行便签、链接长度不同，底部操作不齐 | 同排卡片拉齐高度，正文弹性增长，页脚统一布局 |
| 低 | 空的历史房间分组占位；登录页黑色块过重 | 隐藏空分组，登录改成浅色故事区，保留少量形状与色彩修饰 |
| 低 | 投屏空闲时缺少明确承载区域 | 增加空状态、操作引导和轻量图标；加载完成后再拍摄预览 |

## 视觉方向

暖白背景配深绿色，减少高饱和强调和深色面积；正文保持清楚，辅助信息降低一级而不缩到难读。便签的米色、链接的灰蓝和游戏图标的浅色只作局部修饰。真实照片与视频是主要视觉内容。颜色、断点和组件约束以根目录 `DESIGN.md` 为准。

## 验证方法

1. 浏览器实机截图：桌面中文与英文控制台、房间列表、登录、邀请、设置、分享；手机参与、加入、游戏、投屏；768px 平板控制台。
2. Playwright 布局矩阵：320 / 390 / 768 / 1280 / 1440px，中文与英文，主持人、参与者、登录、加入；检查页面及控件横向溢出。
3. 弹窗专项：320 / 390 / 768 / 1440px，滚到底部后标题仍在顶部，Escape 关闭，返回触发控件的焦点。
4. axe-core：登录、加入、房间列表、主持人、设置弹窗、游戏库、投屏和游戏运行状态，检查 WCAG A/AA 可自动检测规则。
5. 真实后端回归：照片上传、精选、投票、双语切换、大屏轮播、导出；真实 LiveKit 屏幕流到两位观看者和公共大屏，停止与轮换发布者。
6. 故障与状态：请求超时、代理 HTML 错误、上传失败重试、处理中禁止关闭、弹窗内错误提示；游戏选择跨同步保持、确认前不提交、词语切换后隐藏。

测试代码在 `web/tests/ui.spec.ts`，原功能回归在 `roomdeck.spec.ts`、`activities.spec.ts`、`network.spec.ts`。响应式检查复用已打开的加入页，仅改变视口与语言，避免把布局检查变成反复查询邀请码的请求压测。产品原有请求频率限制保持启用。

## 部署与兼容范围

最终验证结果（2026-09-10）：生产构建与类型检查通过；343 个中英文键及插值变量一致；8 项端到端测试全部通过，完整运行耗时 31.3 秒。测试内所覆盖页面和游戏状态的 axe-core A/AA 扫描没有发现违规。实机预览共 13 张，截图采集没有页面脚本错误。阶段性检查发现的卧底词提示对比度不足已通过加深次级文字修正。

可直接打开 `ui-preview.html`，切换页面与改版前后截图进行对照。

动效追加后的最终回归为 10 项全部通过（39.8 秒），343 个双语键一致。新增导航连续定位、弹窗双向动画、键盘即时响应与减少动态效果测试。实际录屏见 `ui-motion.html`，完整动作规格见 `MOTION.md`。

本次没有修改数据库、文件映射、服务器接口或 Compose 服务拓扑。构建后的前端替换原有静态资源即可，Docker 仍按原流程构建部署。新增 axe-core 仅为开发测试依赖，不进入前端运行包。照片、文件、导出、投屏与游戏的数据路径保持原状。

浏览器验证环境为本机 Chromium；投屏由真实 LiveKit 配合自动化屏幕源验证。未将自动检查描述为完整 WCAG 认证，也未声称已验证所有手机浏览器、电视设备或公网 TURN 网络。

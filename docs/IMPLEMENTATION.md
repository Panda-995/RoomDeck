# 当前实现状态 / Implementation status

版本：0.2.0 开发版。产品设计文档是目标规范，本文记录实际边界。

2026-09-10 新增：整目录宿主机映射和文件/ZIP 路径清单；LiveKit 多人观看投屏（每人可轮流发起，一位发布者）；谁是卧底、骰子猜点数；v1 → v2 数据库迁移。游戏规则见 [GAMES.md](GAMES.md)，媒体网络要求见 [SCREEN-SHARING.md](SCREEN-SHARING.md)。

2026-09-11 新增：断线恢复与标签页草稿、分片续传、指定投票上屏、投屏申请/审批/排队、表情与弹幕，数据库自动迁移至 v6。详见 [功能说明与边界](FEATURES-2026-09.md)。

投屏支持自由轮流、排队和主持人审批，不支持多画面拼接；同一会话每房最多 4 个未过期媒体连接。大屏可切换房间内容与当前投屏。媒体信令通过应用权限代理，撤销检查周期 3 秒、客户端租约 45 秒；网络故障时不保证瞬时断流。无默认录制、无原生手机捕获端。谁是卧底与骰子游戏为手动推进阶段；你画我猜支持 90 秒自动到时揭晓、手动进入下一轮。原会话可恢复，丢失 Cookie 后不能凭昵称找回座位。

Go + SQLite + Vue/TypeScript 已连接真实数据；中英双语覆盖界面与服务端错误。房间、加入、上传、内容管理、投票、大屏、导出与清理均已实现。Docker 和原生服务使用同一套功能，没有精简模式。

|目标设计|当前实现|
|---|---|
|增量事件重放|房间与互动使用独立失效通知，互动只读取权限过滤的互动数据；房间重连全量同步，无完整事件日志重放|
|大屏渲染 ACK|显示当前配置和连接数；尚无渲染 ACK，不宣称“已在电视生效”|
|异步图片任务队列|流式上传后在请求内处理，独立信号量控制并发；UI 区分上传与处理|
|分步/续传上传|4 MiB 分片、配额预留、校验和幂等完成；服务重启保留分片，刷新后重选原文件续传|
|分页|每房上限 2,000 内容项，全量轻量快照，照片懒加载|
|上传并发 2|前端最多两个文件，单文件串行分片，图片处理并发 1；后台维护持久上传记录|
|任务自动恢复重试|导出任务持久化，重启后未完成任务标记失败，可重新创建|
|可刷新导出|可重新生成最新快照；保留上一次成功文件直到新任务完成，缓存最多 6 小时|
|Moderator、审批与审核队列|主持人可审批投屏与弹幕；没有独立 Moderator 账户角色|
|HEIC / 视频转码|未实现，作为普通文件可上传下载；JPEG/PNG/WebP 全部部署方式一致|
|多人主持人账户|当前单管理员拥有房间|

默认每房 50 人、2 GB、12 小时活动、结束后保留 24 小时。容量、人数和保留期在设置调整。实例最多 100 房间。照片 20 MB/60 MP，文件 200 MB。照片临时额外预留 16 MB，提交后按实际原件与派生文件计费。

导出在短锁内创建文件硬链接快照（不支持时回退私有副本），然后在修改锁外压缩。新分享不进入已开始的快照。空间预算按原件两倍加 256 MB 校验，兼容副本回退。到期立即拒绝访问，物理清理在后台完成。匿名投票按会话去重，不认证自然人。

服务端测试覆盖权限隔离、上传配额、关闭竞态、附件安全、投票去重/隐藏、导出、WebSocket、初始化、锁与恢复；浏览器覆盖三端、中英切换。仍需真实手机、微信内置浏览器、电视和大规模负载验证。

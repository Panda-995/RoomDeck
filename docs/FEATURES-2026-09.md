# RoomDeck 互动与可靠性功能说明

2026-09-11，开发版。按恢复基础、指定投票上屏、上传续传、投屏排队、表情与弹幕的顺序实现。本文记录实际行为；原始规划见 [NEXT-FEATURES.md](NEXT-FEATURES.md)。

## 使用入口

| 功能 | 入口 | 已实现行为 |
| --- | --- | --- |
| 断线恢复 | 房间标题下的连接状态 | 区分离线、重连与同步；网络恢复及返回页面时同步；带随机抖动的指数退避 |
| 草稿恢复 | 分享内容 → 便签、链接、投票 | 当前浏览器标签页刷新后恢复表单；按房间和身份隔离，成功提交后清除 |
| 指定投票 | 主持人右侧现场大屏 → 投票 | 选择具体投票；投票卡片更多菜单可一键上屏；隐藏票数时仍展示选项 |
| 上传续传 | 分享内容 → 照片 / 文件；房间中的上传任务入口 | 暂停、重试、关闭弹窗后继续；刷新后重新选择原文件，仅补传缺失分片 |
| 投屏排队 | 投屏 → 投屏方式 | 自由、顺序排队、主持人审核；批准、撤回、移出、叫下一位；30 秒叫号 |
| 表情 | 内容卡片下方 | 六种表情，每人每条内容一种；切换、取消、实时汇总 |
| 弹幕 | 内容页 → 现场互动 | 主持人开启直接发送或审核后发送，支持审核、拒绝与清空 |

所有新增状态、按钮与错误均提供中文和英文。手机仍使用原底部导航；投屏轮到用户时隐藏空状态插图，优先显示开始分享按钮。

## 数据与恢复

数据库迁移至版本 6，旧房间与成品文件路径保留。新增持久上传会话、投屏申请、表情和短时弹幕记录；内容同步版本与设置编辑版本分别维护。

上传以 4 MiB 为分片，浏览器同时最多处理两个文件，服务端每个身份最多三个未完成任务、实例最多五十个。照片仍为 20 MiB、文件为 200 MiB，不因续传提高限制。分片在 Worker 中计算 SHA-256，服务端再次校验；刷新后重选文件会核对分片摘要，不能把同名的另一个文件拼进原任务。摘要实现使用 [noble-hashes](https://github.com/paulmillr/noble-hashes)，随前端打包，无在线依赖。

未完成数据在 `/data/uploads/<room_id>/<upload_id>/`；既有 `ROOMDECK_DATA_PATH:/data` 映射同时覆盖该目录，无新增挂载要求。完成后仍进入 `rooms/<room_id>/<content_id>.original` 等原结构，存储清单和 ZIP 仅收录成品。

服务启动根据上传记录重算预留容量；分片不会随旧 tmp 清理。完成时内容 ID 与上传 ID 一致，内容发布与上传完成状态在同一数据库事务内提交。完成响应丢失后再次查询或完成得到同一 ID。文件和图片处理复用现有管线，失败时保留有效分片供重试。

任务最后有效进度后保留最多 24 小时，总寿命最多 72 小时，并受房间活动截止时间限制。清理每分钟执行，回收过期/关闭房间任务和孤儿目录。临时合并会同时占用分片与成品空间；磁盘余量不足时明确拒绝，不绕过配额。

## 投票与投屏

投票上屏以事务设置展示目标及精选状态；跨房间、隐藏或非投票内容不能作为目标。隐藏、删除或取消精选当前投票会清空目标，不悄悄改播另一题。结果隐藏由后端执行。

大屏内容与屏幕分享可单独切换：切到投票会停止该大屏的媒体订阅，其他参与者继续观看；切回屏幕分享可重新加入当前发布。黑屏和房间结束优先于内容与媒体展示。

排队保留一位发布者、多位观看者。主持人批准后进入队列，空闲时自动叫号；超过 30 秒未开始则跳过。短暂离线成员保留最多 60 秒，之后需重新申请。媒体租约仍为 45 秒；旧媒体权限未成功撤销前不交接新发布者。重启使旧叫号和发布申请失效，候场记录保留并在访问队列时重新检查。

用户必须主动点开始分享并选择屏幕，不能后台自动采集。浏览器原有 HTTPS/屏幕采集兼容条件不变。

## 互动展示与同步

新房间默认允许表情、关闭弹幕。弹幕每人五秒最多一条、每分钟最多十条；房间每秒最多五条、等待展示和审核的有效消息合计最多二十条。消息最多六十字，纯文本渲染。

待审核消息仅主持人和发送者可见，五分钟到期；批准后的消息三十秒有效，弹幕数据最长保留一天。大屏独立底部区域最多展示两条，每条最多八秒；投票页使用静态消息，屏幕分享期间隐藏，减少动态效果设置下取消滚动。背景层不截获点击，不能覆盖二维码和投票选项。

WebSocket 为互动单独发送合并失效通知，前端只读取按角色过滤的互动数据，不因一次表情重新获取全房间内容。断线时通过低频轮询兜底；消息按 ID 与有效期去重，不承诺逐帧同步或一定在电视上播放。

## 明确的实现边界

- 当前标签页的文字草稿保存在 sessionStorage；没有把整个文件复制进浏览器数据库。关闭浏览器后文字草稿不保证恢复，文件任务可从服务端恢复清单，但需重新选择原文件。
- 最终图片处理仍在完成请求中串行受限执行，尚未引入独立异步任务服务；处理中不开放取消。超时后可查询并重试同一完成任务。
- 队列采用空闲时自动叫号，尚无拖拽排序、预约时间或多屏同时发布。部分失效申请会直接从活跃队列消失，可重新申请。
- 上传列表展示当前身份自己的任务；尚无主持人集中取消其他人的上传界面。
- 弹幕使用独立底部区域，投票页静态显示；不提供永久聊天室、播放 ACK 或投递必达保证。
- 保持单 RoomDeck 实例，不支持多个应用进程共享同一个数据目录。新增功能没有引入 Redis、对象存储、新端口或外部审核服务。

## 验证与部署

已加入后端测试：上传服务重启恢复、分片内容冲突、完成幂等与配额、指定投票与版本冲突、表情去重、审核权限和投屏叫号过期。

浏览器回归覆盖真实 LiveKit 多人观看、投票与投屏切换、审核后接棒、刷新只补传缺片、断网草稿恢复、弹幕审批、大屏隐藏结果、中英文响应式和无障碍扫描。测试截图使用隔离房间，见 [新功能预览](features-preview.html)。最终运行结果见 [VALIDATION.md](VALIDATION.md)。

Compose 服务和启动命令不变。本机无 Docker Engine，因此实际容器重启、多架构镜像和真实手机/电视验收仍待目标环境验证。升级前停止应用并备份完整数据目录；旧程序不能直接打开版本 6 数据库，回滚需要匹配的旧数据备份。
